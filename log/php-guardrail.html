PHP security guardrail

A runtime guardrail that protects legacy and modern PHP servers from common exploits without changing application code.

WhenOct 2026 – Present
WhereRemote
StatusBuilt and tested locally

The situation

A large share of the web still runs on PHP, much of it on versions that no longer get security patches, and rewriting those systems is slow and costly. In October 2026 I built a guardrail at Future-AI that loads before any application code runs and blocks known attack patterns, so old systems get protection without a rewrite.

What I did

  • Built the guardrail as a runtime layer that inspects each request before the application executes.
  • Blocks CGI parameter injection, PHP object injection, stream-wrapper file inclusion, path traversal and command chaining, and stops uploaded web shells from running.
  • Adds missing security headers and writes an audit log in SIEM format, with an audit-only mode for testing.
  • Tested against 44 exploit vectors and 21 normal CMS traffic cases to check for false positives.
  • Measured overhead at about 16 microseconds per request on average across 20,000 runs.
  • Covered PHP 5.6 to 8.4 on NGINX, Apache and LiteSpeed, with WordPress, Drupal, Joomla and Laravel.

What I carried forward
